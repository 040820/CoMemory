# 分项置信度与证据评价实施计划

**Goal:** 为精简三层记忆增加可追溯的抽取、证据和关系评价，保持追加保存语义。
**Architecture:** 中层 Fact/Assertion 保存抽取分数和评价 ID；独立 confidence_storage
保存 fact_evaluations、evidence_links、relation_evaluations；上层 Link 只引用 evaluation_id。
运行时默认关闭，独立 CLI 可对新目录中的图副本初始化或进行有限的模型评价。
**Tech Stack:** Python 标准库、现有 LLMManager、既有 pickle 图格式。
**Spec:** 本轮用户批准的三类分项置信度设计；未评估=null，LLM 分数未校准，
不按固定阈值覆盖历史，不增加新图层，不修改正在运行的冻结 sample0 快照。

## 全局约束
- 代码功能和模块用途使用详细中文注释。
- 保留原始 Triple、Chunk、旧事实及候选关联，禁止把相似度当作置信度。
- 分开保存支持方向与分数；局部模型评价不代表完整证据链确认。
- 不改用户未提交文件；不重启、不轮询现有构图任务。

## 实施步骤
- [x] 1. 标准库独立模块：注册三类记录、稳定 ID、引用和 null 分数；先写失败测试。
- [x] 2. 有限模型评价：校验 JSON、分数、连续引文与输入引用；失败显式留档，取消继续传播。
- [x] 3. 精简格式保存/加载接入、独立副本 CLI 和使用说明；测试往返不丢记录。
- [ ] 4. 运行固定输入检查、审阅变更、提交和服务器同步；不启动全量评价。

实施决定：沿用当前工作区，只修改本任务干净文件；用户未提交文件保留。
固定输入回归包含评分重试失败、来源变化、时间未知、同 Chunk 依赖和取消传播。
独立审阅发现的来源换绑与纠正时间门控问题已补充失败测试并修复。

检查记录：置信度固定输入 11 项、精简持久化 6 项、实体索引 13 项、多关系 8 项、
Triple 来源 5 项，共 43 项通过。另使用人工固定对话进行本地 vLLM 接口检查：
首次事实评价因 length 截断明确失败/null；紧凑输出提示下事实和证据评价成功，
关系评价成功返回 uncertain。它仅验证接口与保守失败行为，不是 LoCoMo 效果验证。
原始失败记录保留于服务器 results/memory_confidence_probe_20261028。

## 重点审阅
旧格式缺少字段、多个证据来自同一 Chunk、模型输出截断/捏造引用、过期输入导致旧分数
被误用、评价副本加载后的再次保存、候选关系被误当作已确认关系。
