# 组会阶段汇报：面向证据可追溯与可信演化的长期记忆系统

汇报日期：2026 年 10 月 28 日

> 阶段定位：已实现三层存储重构、相关旧记忆召回、候选关系记录及分项置信度评价原型；尚未完成多证据融合、完整解释链验证和最终演化决策。以下区分旧版本真实数据实验、新版本功能检查和待验收构图任务。

## 1. 研究问题与目标

基于 LiCoMemory，研究长期对话中的新信息如何影响历史记忆，并使这种影响能够被原始证据解释。

需要解决三个问题：

1. 新信息写入后，能否找到同一事件或状态对应的历史事实？
2. 如何区分独立新增、补充、并存、冲突、现实变化与历史纠正？
3. 如何说明关系判断依据，并在证据不足时保留不确定性？

例如，“过去说活动在 7 日，现在说记错了、实际是 6 日”，只有确认两段话指向同一次活动，才能支持日期纠正；不能只因主体相同、值不同就覆盖历史。

## 2. 当前图结构：三层存储，评价独立记录

| 层次 | 保存内容 | 主要职责 |
| --- | --- | --- |
| 下层 Chunk | 完整原始对话、会话 ID、会话时间 | 保留证据，支持回查原话 |
| 中层实体索引与事实表 | 原始 Triple，以及来源断言、时间/属性断言 | 索引具体事实，保留时间、模态、作用域及来源 |
| 上层 Event Index | 事件分组与事实之间的候选关系 | 组织事实和演化线索，不重复堆放事实正文 |

实体关联图使用简单关联边索引独立 Triple ID。相同实体之间的不同谓词、方向、不同 Chunk 来源分别保存，不因共用实体对而覆盖。

上层事件分组是来源锚点，不能直接视为跨 Chunk 事件身份已经确认。普通状态断言也不必强制建立事件节点。

置信度记录不新增第四层：

- 中层记录抽取分数和评价 ID。
- 独立 EvidenceLink 记录证据的支持/反驳方向、分数、原文位置。
- 独立 RelationEvaluation 记录新旧事实关系的检查项、证据、理由及分数，上层 Link 只引用其 ID。

优点是保留历史、减少上层重复、支持来源追溯，并能区分抽取错误、证据不足与关系判断错误。

## 3. 当前写入与演化流程

```text
新会话
  → 切分 Chunk，保存原话
  → 抽取实体与关系，保存原始 Triple
  → 更新实体关联索引
  → 抽取有来源支持的事件/状态断言
  → 召回少量相关历史事实
  → LLM 逐对提出新旧关系
  → 追加事实，保存候选关联和写入轨迹
```

状态类事实采用两路候选召回：StateSlot 结构化召回与 BGE-M3 语义召回，合并、去重后控制逐对判断预算。事件类事实目前沿用事件候选召回，并未全部统一为同一双路流程。

写入阶段不把“候选纠正/替换”直接当作已成立的演化关系，不使旧事实失效。当前更准确地称为“演化线索发现与记录”。

分项评价通过独立入口显式执行，构图启用该功能时只初始化评价记录，不自动增加全量评分调用。

## 4. 当前问答检索流程

```text
用户问题
  → 保留完整问题语义，分析实体、关系与目标
  → 与 Triple＋Chunk 语义单元匹配
  → 利用中层关联结构扩展候选
  → 去重排序，返回 Top-5 Chunk
  → 有限展开对应事实、候选关联及已有评价
  → LLM 基于原文回答
```

不要求候选必须先经过 Session Summary 筛选。评价记录目前作为解释材料展示，不据此自动重排 Chunk、确认纠正或执行记忆覆盖。

## 5. 已完成实验及能够支持的结论

### 5.1 旧版本 sample0 写入期召回对比

实验版本为 `46e593e`，不是最新精简结构或最新置信度版本。

| 项目 | 结果 |
| --- | --- |
| 输入规模 | 19 个会话、214 个 Chunk |
| 写入来源断言 | 208 条，其中 167 条被分类为事件、41 条为状态 |
| 候选关联 | 753 条，均未确认为最终演化关系 |
| 比较方法 | 旧方式、仅 StateSlot、仅 BGE-M3、双路融合 |
| 比较范围 | 状态类断言；41 条中 39 条具有同主体历史 |

主要发现：

- 双路与纯语义在 41 条已写入状态断言中，有 38 条返回相同候选集合，结构化路径补充有限。
- 39/41 条状态归一化未通过证据检查，仅 2 条实际应用归一化。
- LLM 辅助标签出现误判，例如把“又养了一只猫”误标为替换。
- 输入来自历史图恢复，Triple 来源不完整：467 条可恢复 Triple 覆盖 183/214 个 Chunk，因此存在数据完整性限制。

结论：该轮实验暴露了归一化、事实质量与辅助标签问题，不能证明双路召回优于原方法。模型正例池内覆盖不是人工标注的 Recall@K。

### 5.2 新结构与置信度功能检查

共 43 项固定输入检查通过：

| 检查内容 | 数量 |
| --- | ---: |
| 分项置信度、失效与保守失败行为 | 11 |
| 精简持久化及保存/加载往返 | 6 |
| 实体与独立事实索引 | 13 |
| 多关系来源保全 | 8 |
| 原始 Triple 持久化与兼容 | 5 |

检查了无效分数、捏造引文、来源变化、旧评分失效、关键条件未知、同 Chunk 派生证据依赖、输出截断和取消传播等情况。

这些结果证明对应程序行为符合测试预期，不代表真实对话上的抽取、推理或问答准确率已提升。

### 5.3 人工固定对话的本地 vLLM 接口检查

使用人工日期纠正输入检查分项评价接口。事实与证据评价可以返回结构化结果；关系评价可以返回 uncertain。首次事实评价出现输出截断，系统明确保存为 failed/null；增加紧凑输出提示后，该固定输入成功返回。

该实验不属于真实 LoCoMo 置信度评测，也不意味着已验证概率校准质量。

## 6. 当前边界与关键问题

1. 数据质量：真实对话的事件/状态分类、时间绑定和槽位归一化仍需人工审计。
2. 候选召回：结构化路径可能过窄，语义路径可能引入宽泛相似但无演化关系的事实。
3. 关系判断：同主体、同谓词、值不同或时间更晚都不足以证明替换。
4. 置信度：当前是未校准模型估计，尚无可靠融合算法或经验证的采纳阈值。
5. 完整链条：尚未完成多来源支持/反驳融合、可靠因果链和最终 CORRECT/REPLACE 决策。

## 7. 下一步实验计划

按依赖关系推进，先解决事实和候选质量，再研究可信决策：

1. 验收新 sample0 构图：检查原始会话覆盖、Triple 来源完整性、事件分组、时间断言和证据绑定。
2. 建立人工标注小集：覆盖重复、补充、并存、冲突、替换、纠正及证据不足，标注应关联的旧事实和原文依据。
3. 重新比较四路召回：在同一事实库、相同候选预算下评估人工 gold Recall@K 与噪声，避免归因混淆。
4. 评价关系判断与分项分数：报告关系分类、误采纳和暂缓判断情况；有明确标注目标后，再进行概率校准与阈值选择。
5. 增加多证据融合：区分独立来源与同源派生证据，纳入反证；再验证完整解释链与最终演化决策。
6. 最后开展端到端消融：固定模型、事实库和 Top-k，比较候选关联/分项评价/融合机制对问答和解释质量的影响。

## 8. 组会口头收尾

目前的阶段成果，是把长期记忆组织为能够追溯来源、保留历史和记录关系依据的结构，并完成了相关旧事实召回及分项评价原型。真实 sample0 的旧版实验说明，当前瓶颈仍在归一化、候选质量和关系误判，尚不能宣称检索或可信演化效果提升。接下来先验收新图、建立人工标注，再验证多证据支持下的关系判断与演化决策。
