# StateSlot 与原始语义双路召回实施记录

## 目标与边界

实现用户已确认的写入期历史匹配：StateSlot 精确召回与 BGE-M3 语义召回并行，合并后由 LLM 判断事实关系，最终由独立证据门控决定更新。保留原检索和事件实例识别逻辑。本轮按用户要求不运行测试、模型或数据集验证。

## 模块及实施步骤

- 新增 `coregraph/hybrid_state_retriever.py`：独立 A/B 召回、历史索引、RRF 排序、路径配额及可追溯日志。
- 新增 `coregraph/state_fact_relation.py`：逐对判断重复、补充、并存、冲突、纠正、替换；模型判断不能直接写入。
- 修改 `event_state_layer.py`：追加 Fact 槽位/主体索引、关系审计记录；不改中层 Triple 或 Chunk。
- 修改 `event_state_writer.py`：归一化前后双路召回，关系判断后复用原有时间及更新门控；不确定结果保留待核查。
- 配置和实验入口显式启用双路模式，历史配置默认仍使用 legacy。
- 添加中文模块说明及详细注释；提交版本并同步服务器，不启动实验。

## 算法约束

对象若为状态取值（例如雇主），不能作为相等过滤条件；若为槽位作用域（例如过敏对象），由 scope 限定。时间用于候选排序与更新门控，不要求新旧时间相等。A 查询全部历史，B 只嵌入原始表达。最终预算默认为 5，分别保护 A/B 首位和当前状态。RRF 分数不是置信度。未标注正确旧事实 ID 前，不计算 Recall@K。
