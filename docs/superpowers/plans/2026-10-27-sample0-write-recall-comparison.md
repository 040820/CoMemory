# sample0 写入期召回对比计划

比较 legacy、structured、semantic、hybrid 的 Top-5；仅评估写入期旧事实召回，不比较问答。使用同一份 214 Chunk、19 Session 的来源图，在共同的新事实/历史快照上运行四路影子召回；hybrid 作为统一上层构建驱动，避免四次抽取造成输入不同。

- 来源只读，独立目录重建 v4 上层；记录旧图 Triple 恢复覆盖率，不混入其它图关系。
- 保存归一前、归一后全部四路候选、完整事实/原文/Triple、排名和分数。
- 最终比较每个新事实最后一次召回；保留未选候选池，LLM 对合并池逐对盲判，不传方法名和排名。
- 生成逐条报告、方法候选差异、模型辅助候选关联率/池内覆盖率及人工标注模板。没有人工 gold，不报告真实 Recall@K，也不把模型判断当事实真值。
- 补充实验脚本合成数据自检和真实小样本预检，确认后启动完整 sample0；后台启动后不持续轮询。
- 冻结脚本/配置/代码指纹，提交 GitHub 同步服务器；不改旧产物或 Baseline。

限制：统一归一化受 hybrid 驱动，这属于固定事实流上的召回对比，不是四种写入系统端到端效果比较。共享缓存意味着方法耗时不适合做速度结论。旧图原始 Triple 可能缺失，完整覆盖不能凭恢复推断。
