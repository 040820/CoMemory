# Evidence Protocol Repair Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 修复已审计的五项问题，复用现有 sample0 图验证引用协议和旁路置信度。

**Architecture:** 写入关系模型选择新旧证据编号，由程序绑定原文；审查模型选择实际展示的片段编号，严格校验来源和位置。置信度按目标断言分组，作为 shadow 报告输出，不改变 Judge 状态或事实有效性。

**Tech Stack:** Python 3.11、unittest、现有 BGE-M3/vLLM、JSON Schema。

**Spec:** 本次用户批准的上一轮审计修复顺序 1–5。

## Global Constraints

- 保留用户已有改动、新图和旧实验产物，全部验证写入新目录。
- 新增代码提供中文功能注释及模块说明书；不修改原版 Baseline 运行逻辑。
- 不新增人为生成 token 上限；保留服务端截断检查和有界协议重试。
- 技术失败单独记录，不当作语义不确定或置信度负样本。
- 不自动覆盖、删除或令旧事实失效；置信度未经校准，只记录。

## Review Focus

- 两端属于同一 Chunk 但原句相距很远：应各自有可核对的展示窗口。
- 编造片段编号、改写、省略号、错绑 Chunk：必须拒绝并记录技术失败。
- 取消任务和网络异常：取消向上传播，网络错误不冒充证据不足。
- 支持不同目标的证据不能混合形成一个更新置信度。
- 断点重放必须限定于源图实际存在的事实，不能把缺失端点静默当作成功。
